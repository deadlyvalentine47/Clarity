# Clarity — Project Notes

## Task

Port the Android app (Kotlin + Jetpack Compose + Room + Hilt) to a Node/browser app so it can be
run and tested with `npm run dev` instead of Android Studio.

Phase 1 (10 screens) complete. Phase 2: repo pulled ~30 commits ahead (123 files, 18.7k Kotlin LOC)
— porting the budget overhaul, habit metrics/journal, notes tree, home sections, themes and the
larger backup format, while fixing the bugs/duplications in master.

**Status (2026-11-01): port complete; Android sources removed; Node app at repo root.** — 20 app routes + not-found, all four smoke scripts pass with
0 console errors, `tsc --noEmit` and `npm run build` clean.

## Decisions

- Stack: **Vite + React 19 + TypeScript**, IndexedDB via **Dexie 4**, plain CSS design tokens.
- Repo root is the Node app. The Android/Kotlin sources were removed once the port
  reached parity (still in git history / `master`).
- Preferences (username, theme, dark mode, home sections) in `localStorage`; app data in IndexedDB.
- **Consolidate duplicated Android budget screens** into: Budget hub → Accounts (list + detail),
  Credit Cards (list + detail), Investments, Metrics. Drop the dead `BudgetScreen.kt`,
  `IncomeScreen`, `SpendingScreen`, `SourceDetailScreen`, `CCSpendsScreen`, `BankScreen`/
  `BanksScreen` split.
- Fix in the port (not reproduce): duplicate accounts/categories, name-based drift, orphaned card
  transactions, broken billing-cycle dates, CCSpends shared-state bug, stale month caches,
  bestStreak never computed, missed-day backfill overwriting data, sortOrder being write-only,
  note drag-drop cycles, non-atomic import, backup ID remapping, dark-mode contrast.
- Habit Weekly/Monthly are no-ops in Android; web treats Weekly as every 7 days from creation and
  Monthly as the same day-of-month (documented improvement).
- Notes `category` is a comma tag list; web treats it consistently as tags (filter matches any tag).
- Images stored in IndexedDB (`noteImages`) and referenced as `![img:uuid]` (Android uses files).
- No default accounts/categories are seeded (Android doesn't either) — kills the duplicate-defaults
  bug at the root.
- Import skips clearing `noteImages` because old backups are JSON-only; local images survive.
- Backups embed note images as base64 data URLs (`noteImages`, ignored by the Android app), so a
  restore is self-contained. Old-app backups carry markers only; their pictures are not recoverable
  automatically (Android 11+ blocks path reads of files it wrote outside MediaStore).
- **Capacitor** is the APK path (local WebView origin `https://localhost`, IndexedDB stays local).
  `android/` is generated by `cap sync`; the APK is built in GitHub Actions, not locally.
- Builds are approval-gated: the `build` job targets the `apk-build` environment, and `master`
  requires the `build` check. One run per PR, newest commit cancels the pending one.

## Constraints

- IndexedDB cannot index booleans — filter `isCompleted/isArchived/isPinned/isDefault/isDeleted`
  in JS, never add them to Dexie `stores()`.
- Un-indexed lookups (e.g. `linkedCardTxnId`) must use `collection.filter()`, not `where()` —
  `where()` on a missing index throws `SchemaError` and aborts the whole Dexie transaction.
- Export JSON must stay Android-compatible (extra fields are ignored by its `ignoreUnknownKeys`).
- Import must be atomic (single Dexie transaction) and remap parent/child IDs.
- Node 18+, no Android SDK. Dev server port 5173.
- Smoke scripts import `/src/db/db.ts` through the Vite dev server, so the dev server must run.
  Set `BRAVE_PATH` if Chromium isn't `/usr/bin/brave`.
- In Puppeteer tests, scope dialog clicks to `.dialog`: the page behind it often has same-named
  chips/buttons (e.g. category filter chips vs. category picker).
- iOS: Capacitor 8 uses SPM (no CocoaPods); `ios/App/App/public`, `capacitor.config.json`
  and `App/build` are generated/ignored. New Swift files must be added to
  `App.xcodeproj/project.pbxproj`; local plugins register in
  `ClarityBridgeViewController.capacitorDidLoad`. The IPA is unsigned — install needs
  AltStore/Sideloadly/Apple team re-signing. iOS background work is best-effort, so the
  23:30 backup runs opportunistically and the snapshot is also copied to
  `Documents/Clarity` on every foreground/background transition.

- 2026-11-01 fixes found while testing:
  - `deleteTransactionCascade` used `where('linkedCardTxnId')` (no index) → SchemaError; now
    `filter()`. Deleting a transaction restores the account balance again.
  - `deleteCardCascade` nulled every bank payment's card link; now card-scoped and also removes
    bank-side rows pointing at the deleted card.
  - Billing cycle now labels the statement window that *ends* in the selected month and clamps
    day 29–31 in short months.
  - Card "outstanding" clamps to 0 for cards in credit, with the credit shown separately
    (hub, card list, card detail, metrics).
  - Habit metrics day cells no longer draw a "today" ring on every unscheduled day; partial days
    show `done/scheduled`; legend updated.
  - Import keeps `noteImages` so `![img:…]` markers don't break.
  - PageHeader wraps on narrow screens; month/year chip filters wrap instead of scrolling.
  - `plural()` helper removes "1 days" strings.
- Tests: `smoke` (20 routes), `smoke:interact`, `smoke:logic` (recurrence, streak, billing clamp,
  card cascade isolation, note tree cycle guard, rename drift, export/import), `smoke:flows`
  (account/card/investment CRUD, bill payment, habit day status, child page, home quick-add /
  complete / habit chip / collapse persistence, round trip). All green, 0 console errors.
- 2026-11-01 Capacitor/APK (commit `368be51` + follow-ups):
  - `android/` project (appId `com.clarity.app`, minSdk 24, compile/target 36), versionCode 2.
  - `HashRouter` on native, safe-area insets for Android 15 edge-to-edge.
  - Export on native offers Save to this device (`SaveFilePlugin`, SAF) and Share. The JSON is
    written to the cache first and only its path crosses the bridge; passing the payload through
    the plugin call killed the app on large backups and left a 0-byte file.
  - Back button steps through screens; only exits from Home after a second press (toast).
  - Onboarding now tracks `onboarded` separately from the username, so importing a backup lands on
    Home instead of asking for a name again.
  - Permissions at launch: notifications only (`POST_NOTIFICATIONS`, `SCHEDULE_EXACT_ALARM`,
    `VIBRATE`). No storage permission anywhere.
  - Pomodoro schedules a local notification so the alarm fires in the background.
  - *Settings → Data*: Export (SAF picker), Import, Clear data (keeps name/theme/home layout).
  - CI publishes the APK to the rolling `apk-latest` release (artifacts are always zips).
  - Uploading a picture needs no permission (system picker -> copy); it is downscaled to 1280px
    JPEG and kept as a blob in IndexedDB, and is now included in backups.
  - Debug signing key committed (`android/app/clarity-debug.p12`) so CI builds upgrade in place.
- 2026-11-01 export crash fix: `SaveFilePlugin` took the whole JSON as a call argument and held it
  across the "Save as" activity — the process died and the picked file stayed 0 bytes. It now takes
  `sourcePath` and stream-copies the cached file (and reports the byte count, which the UI checks).
  Export shows a dialog with both **Save to this device** (MediaStore -> `Downloads/Clarity/` on
  Android 10+, SAF picker on 7-9) and **Share**. Compact JSON (no indent) keeps large backups
  smaller. versionCode 3.

- 2026-11-02 home habits + backup schedule:
  - Home habit chips now use `compareHabits` (sortOrder), matching the Habits screen
    order, including drag-reordered lists.
  - Habits completed today (on time or late) are hidden from the home strip; the
    habit itself is untouched. When all are done the section shows "All habits
    done for today" instead of the empty strip. The `x/y done` meta still counts all.
  - Nightly backup: `setInitialDelay` is relative to the work's original enqueue
    time, so re-running `schedule()` with `UPDATE` on every launch slid the target
    earlier until it landed in the past and fired on app open (20:46:59 on Nov 1).
    `BackupScheduler` now pins the next run with the absolute
    `setNextScheduleTimeOverride(next 23:30 local)` and the worker re-pins after
    each run, so relaunches and delayed runs can't shift it. versionCode 5 / 1.4.
  - Verified with a Puppeteer probe: chips render `a,c,b` for sortOrder 10,20,30,
    disappear on completion, habit rows still exist; `smoke:flows` + build green.
