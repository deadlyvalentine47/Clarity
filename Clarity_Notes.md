# Clarity — Project Notes

## Task

Port the Android app (Kotlin + Jetpack Compose + Room + Hilt) to a Node/browser app so it can be
run and tested with `npm run dev` instead of Android Studio.

Phase 1 (10 screens) complete. Phase 2: repo pulled ~30 commits ahead (123 files, 18.7k Kotlin LOC)
— porting the budget overhaul, habit metrics/journal, notes tree, home sections, themes and the
larger backup format, while fixing the bugs/duplications in master.

**Status (2026-11-05): port complete; Android sources removed; Node app at repo root.** — 23 app routes + not-found (Runs added 2026-11-05), all four smoke scripts pass with
0 console errors, `tsc --noEmit` and `npm run build` clean.

## Decisions

- Stack: **Vite + React 19 + TypeScript**, IndexedDB via **Dexie 4**, plain CSS design tokens.
- Repo root is the Node app. The Android/Kotlin sources were removed once the port
  reached parity (still in git history / `master`).
- Preferences (username, theme, dark mode, home sections) in `localStorage`; app data in IndexedDB.
- **Consolidate duplicated Android budget screens** into: Budget hub → Accounts (list + detail),
  Credit Cards (list + detail), Investments, Metrics. Drop the dead `BudgetScreen.kt`,
  `IncomeScreen`, `SpendingScreen`, `SourceDetailScreen`, `CCSpendsScreen`, `BankScreen`/
  `BanksScreen` split.
- Fix in the port (not reproduce): duplicate accounts/categories, name-based drift, orphaned card
  transactions, broken billing-cycle dates, CCSpends shared-state bug, stale month caches,
  bestStreak never computed, missed-day backfill overwriting data, sortOrder being write-only,
  note drag-drop cycles, non-atomic import, backup ID remapping, dark-mode contrast.
- Habit Weekly/Monthly are no-ops in Android; web treats Weekly as every 7 days from creation and
  Monthly as the same day-of-month (documented improvement).
- Any flat habit list (home strip) must flatten `buildTopLevelRows`, never a flat `compareHabits`
  sort: `sortOrder` restarts at 10 inside every group, so a flat sort interleaves groups.
- Notes `category` is a comma tag list; web treats it consistently as tags (filter matches any tag).
- Images stored in IndexedDB (`noteImages`) and referenced as `![img:uuid]` (Android uses files).
- No default accounts/categories are seeded (Android doesn't either) — kills the duplicate-defaults
  bug at the root.
- Import skips clearing `noteImages` because old backups are JSON-only; local images survive.
- Backups embed note images as base64 data URLs (`noteImages`, ignored by the Android app), so a
  restore is self-contained. Old-app backups carry markers only; their pictures are not recoverable
  automatically (Android 11+ blocks path reads of files it wrote outside MediaStore).
- **Capacitor** is the APK path (local WebView origin `https://localhost`, IndexedDB stays local).
  `android/` is generated by `cap sync`; the APK is built in GitHub Actions, not locally.
- Builds are approval-gated: the `build` job targets the `apk-build` environment, and `master`
  requires the `build` check. One run per PR, newest commit cancels the pending one.

## Constraints

- IndexedDB cannot index booleans — filter `isCompleted/isArchived/isPinned/isDefault/isDeleted`
  in JS, never add them to Dexie `stores()`.
- Un-indexed lookups (e.g. `linkedCardTxnId`) must use `collection.filter()`, not `where()` —
  `where()` on a missing index throws `SchemaError` and aborts the whole Dexie transaction.
- Export JSON must stay Android-compatible (extra fields are ignored by its `ignoreUnknownKeys`).
- Import must be atomic (single Dexie transaction) and remap parent/child IDs.
- Node 18+, no Android SDK. Dev server port 5173.
- Smoke scripts import `/src/db/db.ts` through the Vite dev server, so the dev server must run.
  Set `BRAVE_PATH` if Chromium isn't `/usr/bin/brave`.
- In Puppeteer tests, scope dialog clicks to `.dialog`: the page behind it often has same-named
  chips/buttons (e.g. category filter chips vs. category picker).
- iOS: Capacitor 8 uses SPM (no CocoaPods); `ios/App/App/public`, `capacitor.config.json`
  and `App/build` are generated/ignored. New Swift files must be added to
  `App.xcodeproj/project.pbxproj`; local plugins register in
  `ClarityBridgeViewController.capacitorDidLoad`. The IPA is unsigned — install needs
  AltStore/Sideloadly/Apple team re-signing. iOS background work is best-effort, so the
  23:30 backup runs opportunistically and the snapshot is also copied to
  `Documents/Clarity` on every foreground/background transition.
- Runs use `@capacitor-community/background-geolocation` 1.3.1. Keep
  `android.useLegacyBridge: true` — the new bridge stalls location after ~5 min in
  the background. No `ACCESS_BACKGROUND_LOCATION` (foreground service only).
  Distance/route is always stored in metres; km/mi is display-only.

- 2026-11-06 dialog focus fix (mobile keyboard closed on every keystroke in the
  Run "Save run" name field):
  - Cause: `Dialog`'s focus-trap effect depended on `[open, onClose]`, and `RunScreen`
    passes an inline `onClose={() => setShowSave(false)}` while `saveName` lives in the
    screen — so each keystroke re-rendered the screen, changed `onClose`, and re-ran the
    effect. Its cleanup called `previouslyFocused.focus()` (the Stop button / body),
    blurring the input; Android/iOS then hide the keyboard.
  - Other dialogs were fine because their inputs own their state, so the parent never
    re-rendered and `onClose` kept its identity.
  - Fix: `Dialog` keeps `onClose` in a ref and the effect now depends on `[open]` only.
    Escape/X/scrim still close, and focus restore now runs only on actual close.
  - Verified with a Puppeteer probe: typing 17 chars into the name field yields 0 blurs
    with focus staying on the input (was 1 blur + focus on `<body>`); Escape still closes.
    `typecheck`, `build`, `smoke`, `smoke:flows` green with 0 console errors.
