2Open findings

Five medium and twelve low items. New-since-v1 findings are marked NEW.

Medium

Medium M1 · Adding a note image still discards text typed while it encodes

src/screens/NoteDetailScreen.tsx:94–108 · onPickImage

saveNoteImage() is awaited, then the marker is inserted into the editContent value captured when the picker opened. Anything typed during the image downscale/re-encode is overwritten by setEditContent(next.content).

Fix: keep the cursor, then merge against the latest state: setEditContent(prev => insertImageMarker(prev, cursor, imageId).content). Capture cursor before the await.

Medium M2 · Runs history and Home load every GPS point of every run NEW

src/screens/RunsScreen.tsx:124–128, src/screens/HomeScreen.tsx:112

Both queries are db.runs.orderBy('startedAt').toArray(). A run can hold 5 000 point objects (RUN_FILTERS.MAX_POINTS), so a few hundred runs means hundreds of thousands of objects decoded on every live-query emission — and Home only needs this week's totals. Rendering is capped at 400 points per SVG (RouteMap.tsx:7), but the read is not.

Fix (preferred): move points to a separate runPoints table keyed by run id (Dexie v9), so the list/Home query stays small and route maps fetch on demand. A cheaper interim step is to query only the visible period and add a small “summary” projection for Home.

Medium M3 · Run history cards are not keyboard reachable NEW

src/screens/RunsScreen.tsx:1023–1046 · RunCard

The card is a plain <div onClick={selecting ? onToggle : onOpen}> with no role, tabIndex or onKeyDown. This re-introduces the exact v1 pattern that Notes/Accounts/Home just fixed, on the newest screen. The group header is a real button, so only the run rows are affected.

Fix: make the card body a <button className="run-card-main"> (with the action row outside it), or restore role="button" tabIndex={0} and Enter/Space handling. Keep the nested ↑/↓/remove buttons' stopPropagation.

Medium M4 · Tap targets below 44 px and unnamed search fields

styles.css:757, :1666; NotesScreen.tsx:154, HabitsScreen.tsx:202; icon buttons in Settings/Notes/Calendar/Goals
  • .checkbox is 24×24 and .tree-toggle 26×26 — both are primary list affordances.
  • Many .icon-btn instances are shrunk inline to 30–34 px (delete/edit actions); the base is 40 px, still under 44.
  • The two remaining search inputs have only a placeholder — no aria-label/<label> (transactions/notes search was removed with Tasks).
  • Field still renders a <label> around multi-button chip groups (note tags, budget category/account, transfer target). A label may wrap only one labelable control.

Fix: 44 px minimum hit area (visual size may stay smaller with padding), aria-label="Search notes"/"Search habits", and change Field to a <div className="field"> with an explicit htmlFor when it contains a single input.

Medium M5 · Empty-state flash and duplicated markup

all list screens · SettingsScreen · .segmented usage

55 of 84 useLiveQuery calls pass [] as the default, so the screen renders its “nothing here yet” state while Dexie resolves; only four detail screens show a loading line. Separately, Segmented was deleted as dead code but the hand-rolled .segmented markup survives in 11 places, and Settings still writes its own section rows instead of CollapsibleHeader.

Fix: default queries to undefined and render a shared skeleton/“Loading…” above the empty state; reintroduce one Segmented component and use CollapsibleHeader in Settings.

Low

Low L1 · Missed-day backfill (and best streak) cap the scan window

src/db/habits.ts:244–254, :108–124

markMissedDays walks forward from creation with guard < 732, so a habit older than two years fills its oldest two years and stops — the opposite of “fill up to yesterday”. computeBestStreak has the same shape with guard < 3660.

Fix: iterate backwards from today - 1 (bounded by creation) and stop when the guard is hit; the recent window is what matters.

Low L2 · “Done” and “Done late” are the same on past days

src/db/habits.ts:134–143

deadlinePassedFor returns true for any key < todayKey, so checking Done on a past day always writes lateCompletions and renders “done late”. Both chips are indistinguishable for history.

Fix: record an explicit non-late completion (or hide the “Done” chip on past days).

Low L3 · Note delete snapshot and image cache

src/db/notes.ts:132–142, :167; src/lib/exportImport.ts

deleteNoteWithDescendants reads db.notes.toArray() before opening the transaction, then deletes that snapshot's ids — a concurrent child write can be orphaned. The module-level urlCache also survives importData, so re-importing a backup that reuses a uuid can show the old blob.

Fix: compute descendants inside the rw transaction; export a clearNoteImageCache() and call it after import.

Low L4 · Back-button listener can leak under StrictMode

src/lib/native.ts:249–268

remove is assigned inside addListener(...).then(); the dev double-mount cleanup runs before the promise resolves, so the first listener is never removed and onExit can fire twice.

Fix: keep the promise/handle and await it in cleanup, or guard with a disposed flag.

Low L5 · Card credit is treated differently by Hub/Home and Metrics

BudgetScreen.tsx:62, HomeScreen.tsx:153 vs budget/MetricsScreen.tsx:80–86

Hub/Home sum Math.max(0, cardOutstanding(card)) per card, so one card at +500 and another at −300 reports ₹500. Metrics nets to ₹200 and adds the credit to net worth. Pick the netting version and share one helper.

Low L6 · Sunset primary buttons are 4.46:1

src/lib/themes.ts:179 · primaryStrong

The contrast fix works for five themes (4.69–6.15:1 white on --primary-strong). Sunset #D4805A darkened by 20 % gives 4.46:1 — a hair under WCAG AA 4.5. Increase the mix to ~0.24 or use dark text on that palette.

Low L7 · The drawer still has no focus trap

src/components/Layout.tsx:52–70, :94–101

Escape, scroll-lock and initial focus are in. Tab can still leave the drawer and reach the page behind it; the scrim remains a bare <div onClick> (fine as a pointer affordance, but not announced). Add the same Tab loop used by Dialog, or use <dialog>.

Low L8 · Habit-metrics day cells expose only title

src/screens/HabitMetricsScreen.tsx:318, :417

Screen readers do not reliably announce title on a <span>. Add an aria-label with the date and done/scheduled count.

Low L9 · Recurring overnight events collapse to one hour / one day NEW

src/db/events.ts:92–99 · eventOccurrence

For a repeating event, the occurrence is rebuilt with the start and end clock times on the same day; when the end is earlier than the start it becomes start + 1 h. A series that starts at 22:00 and ends at 02:00 loses both the next-day end and its multi-day span (one-off events are handled correctly by eventOccursOn).

Fix: store the end as a duration from the start (or compare date parts) and carry it into the occurrence, and let eventOccursOn test the start/end overlap for recurring rows too.

Low L10 · Deleting a session's last run leaves an invisible empty session NEW

src/screens/RunDetailScreen.tsx:268–274; src/screens/RunsScreen.tsx:166–171

Run deletion is a bare db.runs.delete(id). runGroups rows are only pruned by session add/move/remove, and the Runs screen filters groups down to those with a visible run. The orphan row is unreachable in the UI (cannot be renamed or deleted) until another run is added to it.

Fix: route deletion through a deleteRun(id) helper that clears/prunes the group, or include empty groups in the list with the existing delete action.

Low L11 · Grouping runs that all sit inside a session inserts the new session at the top NEW

src/db/runGroups.ts:169–176

insertAt searches only top-level rows; when every selected run is nested in another session, the index is -1 and the new session is inserted at position 0 instead of where those runs were. The runs still move correctly — only the visible position is surprising.

Fix: resolve a selected run's containing group and use that group's row index when no top-level run matches.

Low L12 · A fresh new Date() in memo deps defeats the memo

src/screens/HabitsScreen.tsx:75, :104; src/screens/budget/AccountsScreen.tsx:22, :40

today/now is created every render and passed as a dependency, so the row/filter memo recomputes on every keystroke or toast. This was called out in v1 and survived the cleanup.

Fix: depend on todayKey/year instead of the Date object, or memoize “today” until midnight.

3Review of the new features

3.1 Runs history — Month/Day/Year filter and sessions

Model is sound. The period control now matches All transactions (same anchor date, clamping on month change, Today), and the session layer is coherent: sortOrder is explicit position with a null fallback to start time; top-level history is newest-first while a session's runs read oldest-first (walk 7:00 → run 7:30 → walk 8:00); a manual move always wins; createRunGroup renumbers to 10/20/30 and inserts the group where its first run sat; new runs get min − 10 once any manual order exists; import/export remaps group ids; and smoke:logic asserts timeline, manual priority, nested move/remove and round-trip.

Behaviour worth documenting: creating the first session switches the list from “never moved” date mode to explicit positions. That is why a later run still lands on top — and why an imported legacy run with a null position can appear above a manually ordered list.

Issues found: M2 (full-track queries), M3 (keyboard access), L10 (orphan session), L11 (nested grouping position). Touch reordering relies on the ↑/↓ buttons and “Add to session”, which is the right call — HTML5 drag is unreliable on mobile.

3.2 All transactions ledger

Clean. Period math is shared with Budget, day groups only appear in month/year mode, self-transfers are excluded from totals, year mode gets month headers, and bank/card rows reuse the existing edit dialogs. No correctness issues found; the only nit is that cardNameById is rebuilt each render (trivial).

3.3 Calendar — recurring, task-capable events

The Tasks → Events rewrite removed two v1 bugs at the source. One-off events now span days (overlap test), recurring events clamp monthly anchors, and a single occurrence can be skipped or deleted without touching the series. The remaining edge is L9 (overnight recurring occurrences).

3.4 Habit groups and Home ordering

sortOrder is group-scoped, and every flat consumer (Home strip) now flattens buildTopLevelRows instead of a flat compareHabits, so groups no longer interleave. Group create/rename/delete/collapse and drag/↑↓ match the Runs session pattern. Only the memo dependency (L12) needs attention.

3.5 Runs live tracking — GPS, barometer, 3D route

Snapshot persistence is throttled (every 5th tick), barometer readings are buffered natively and drained rather than pushed over the bridge, the simulator is behind import.meta.env.DEV, and RouteMap caps rendering at 400 points. No leaks found in the new 3D component; only the list-query cost above.

4Security posture

Still clean: no dangerouslySetInnerHTML, innerHTML, eval or new Function in src/; markdown renders as React elements; the only dynamic URL is a local blob:; the WebView stays on https://localhost with no cleartext or navigation allowance; the production build carries a CSP; imports are size-capped and image MIME-restricted; CI runs least-privilege with SHA-pinned actions and removes the decoded release key.

Two accepted risks remain, both documented: the committed debug keystore (debug-only upgrade convenience) and the LAN-bound dev server (needed for device testing). The only hardening gap is per-field validation for three imported tables, which is schema hygiene rather than an exploit path.

5Performance & maintainability

  • Runs points — the one query that does not scale (M2). Split the track into its own table; list and Home stay small.
  • Memo churn — new Date() dependencies in Habits/Accounts (L12) and a few per-render maps/arrays (e.g. cardNameById in All transactions).
  • Streak scans — computeBestStreak re-walks history on writes; the stored bestStreak is already kept as a running max, so the full scan can be limited to first computation.
  • Duplication — 11 hand-rolled .segmented blocks and 5 Settings section headers remain; the budget summary reduce is still open-coded in Budget/Home/Metrics/Cards (v1's summarizeBudget() suggestion was not taken).
  • Dead weight — src/lib/demoRuns.ts (~250 lines) is only imported by scripts/scenarios.mjs; it is tree-shaken out of the app but would be better placed under scripts/. The remaining unused exports (compareRunOrder, groupStartedAt, geo constants/types) are internal API surface, not the 40-symbol cleanup of v1.
